### ① 「本地 / 离线」的口径

**一处措辞已改。** 界面一体化并不等于支持离线部署——您说得对。

**两个义项分开了。** 「本地」＝本仓实现、本部署管理（与 RAGFlow 等外部来源相区别的内置口径）；「离线」＝各组件均可指向部署环境内运行（本地模型与自托管解析、存储等选项）。

**逐组件清单已成表（§7）。** 十行，逐组件给出可部署位置、哪些内容会离开部署环境（云腿那几行逐条写明）、所需资源与依赖；并注明「自托管」不等于「不出域」。要点：读取/转换/切分在扩展进程内、本步骤不离开部署环境；业务数据、文件、Qdrant 在环境内；解析、嵌入、稀疏、重排、图片说明、回答模型六类各自列出云与本机选项。

**可切到自托管的接入点。** 解析＝`mineru-local`（本地 MinerU 4.x 服务，不带鉴权、只应内网暴露）；嵌入＝`openai-compatible`（指向任意 OpenAI 嵌入形状端点）；稀疏＝本地 BM25 / 独立 TEI 稀疏服务 / 跟随双路嵌入（DashScope、火山方舟）；重排＝Cohere/Jina/TEI 形状；图片说明与回答模型＝引用模型条目、可指向本机服务。均为「首期切片中重新验收」的起点。

**各组件都有环境内选项。** 解析、嵌入、稀疏、重排、图片说明与回答模型这六类会离开部署环境的计算都有环境内实现；向量存储可环境内自托管。依赖、模型权重与资源由部署方准备。

### ② scope、资源标识与配置归属

**一库一对话。** 每段对话只绑定并检索一个库；绑定贯穿新建对话、后续提问、历史恢复与子代理调用，切换库不改绑、不混用消息与引用（§4.1）。

**授权＝四层交集（§4.1 表）。** operator 策略（是否启用扩展与该来源、是否允许访问目标库）× 用户所有权（绑定库及其文档、派生产物）× agent 权限（该 agent 是否可用知识检索）× 对话绑定与消息 scope（只允许绑定库，scope 不能扩大或改变绑定）。

**资源 ID 带 provider 标识。** 内置库与 RAGFlow 等来源可区分；provider 指来源类别、不是模型厂商；具体编码与共享契约一起确定；既有外部来源的对话与 scope 语义不改写（§4.1）。

**范围映射到上游 `selected`。** 单库＝`selected` + `dataset_ids` 仅含该绑定库的资源 ID；不新增范围选择控件、不重定义 `all`。`metadata.kb_id` 只表示选择、不单独授权——服务端核对持久化绑定、当前用户与有效 scope，不一致直接拒绝（§4.1）。

**配置归属。** 通用检索策略、scope 与 agent 装配沿用上游 `knowledge_base` 体系；本地扩展只管理自己的解析、模型服务、存储与索引参数；开发分支的 `rag` 配置是复用来源，不成为第二套含义重叠的总开关（§4.3）。

**现状如实说明。** 当前分支的切库隔离尚未端到端保证（前端切库不重置会话、后端不校验线程既有绑定与请求一致），已列为首期必须补齐的约束（§2.2、§4.1）。

### ③ 陈旧、分路状态、删除与旧 worker

**首期没有图谱/wiki 派生态，「编辑后陈旧」问题不存在。** 切片编辑、图谱、wiki 均后置（§10.1）；后续引入时须成套定义失效时机、重建期间是否可查、各路可用状态（§5.3 末）。首期与一致性相关的机制在索引层：不兼容配置变更先持久暂停受影响库、逐库重建成功后恢复，期间不混用新旧向量、不以空结果掩盖暂停（§2.3）。

**状态按三段表达（§5.2）。** 解析、图片说明、索引各自有结果，能表达完整成功/明确降级/失败；不保留空转的 graph/wiki 状态；向量部分成功不能折算为整篇 `ready`（§3.1 步骤 6）。失败/降级走整篇重试：保留文档 ID；受理时移除原有切片，新切片随写入逐步可被检索；结束后按四档发布（完整成功/降级可再试/失败可再试/库级暂停优先，§5.2 表）。

**删除四条不变量（§5.3）。** ① 先使检索与读取不可达——删除受理后该文档不再出现在检索结果与来源读取中，切片读取、图片预览和原件下载明确失败，向量删除失败仅记录日志、不恢复访问；② 再完成其余清理——同步删除派生数据、业务行与源文件，各步幂等，失败仅记录日志、不阻塞其余删除；③ 中断恢复——重启时未完成的文档（非终态）重新入队继续处理，进程内队列只用于当次执行；④ 旧任务隔离——删除或重试后，旧 worker 与外部存储的晚到写入都不能复活内容。

**按不变量验收，而非按顺序假设。** 仅在写入前查一次「文档还在」或依赖清理步骤顺序都不够；需在关键阶段注入中断，验证重启恢复与并发行为（§5.3）。

### ④ 工具可见性之外的可选性

**交付形态：仓内可选扩展（§6.1 对照表）。** 依赖随可选包安装（不含图谱、视频等后置依赖）；worker 按扩展生命周期启停；扩展表用私有 `MetaData`、统一表前缀与独立 Alembic 版本表，仅启用时迁移。代价如实列：包边界与兼容性维护成本、最小前端与来源契约仍需核心适配（不声称零核心改动）。

**未启用＝不留痕（§6.2）。** 不创建扩展表、不启动知识 worker、不探测模型/解析/Qdrant 服务；前端不开放操作入口、不轮询扩展 API；基础部署不强制依赖 Qdrant 启动。

**迁移对齐（§6.2）。** 已核对上游主迁移 head 为 `0026_mcp_task_lease_tokens`；不复制旧开发分支整串迁移、不修改已发布历史的执行条件，正式实施时重新确认。

**故障与备份（§6.3）。** 六类故障各有隔离要求：如重排失败按 RRF 次序返回并标记降级、Qdrant 不可用时索引与检索报告不可用但已受理删除仍禁读、普通聊天与其他来源不被拖垮。备份含业务数据与所有权、源文件、解析产物、索引配置/版本与重建材料；恢复旧快照会把其后已删除的内容带回来，须在开放知识读取与检索前核对并重新执行这些删除（§6.3）。

**停用与卸载。** 均保留数据；永久删除是独立明确的操作；重新启用时检查版本并恢复未完成任务（§6.2）。

### ⑤ 每期独立可用

**首期＝一个完整文档闭环。** 上传 → 解析正文与图片 → 保存原件与产物 → 图片说明与结构化切分 → 索引 → 库内混合检索与重排 → 库内对话回答及可核验引用；所有权校验、失败重试、删除恢复随链交付（§1、§3）。

**检索面只留一个工具（§3.2）。** 混合检索（稠密＋稀疏召回 → RRF 融合 → 重排）是唯一入口，不存在依赖后续能力的第二、三路工具；重排失败降级到 RRF 次序并明示。

**最小管理界面与库内对话栏随首期（§2.2）。** 建库/上传/状态/失败与降级重试/删除/原件下载/只读核验，加每库自己的对话栏与历史。与您的建议有一处差别：您建议最小 UI 随后补，本提案把它提前到首期，以便首期即可完成配置、排障与核验——这是本次提交评审的范围选择，不表示已获批准。

**后置清单与顺序（§10.1）。** 图谱/wiki、视频、可视化探索、切片编辑、评测趋势等全部后置；后续每项须能独立说明可用闭环与数据责任，不预设统一顺序。

**独立验收（§9）。** A1–A12 逐项可判定，A6/A9 覆盖所有权与删除边界。

### ⑥ 基础评测前移

**固定材料与 baseline（§8.1）。** 许可清楚的语料、解析产物、切分与来源/切片标识、索引输入指纹、查询与相关来源标注、`top_k` 与候选数口径、解析/切分/嵌入/稀疏/重排的版本与参数；指标 Recall@k / Hit@k / MRR，带同条件 baseline 对比；按文字/表格/图片分组报告，避免总分掩盖图片链失效。当前草案不把格式矩阵与首份 baseline 当已完成证据，交付时补齐。

**无云凭据的 CI（§8.2）。** 录制工件＝解析产物、图片说明、文档与查询两侧向量、重排响应；切分、索引写入、召回、RRF、重排结果应用、权限与 scope、来源 artifact、指标计算全部真实执行。不能录制最终命中列表冒充检索测试，也不能只录查询向量、继续从云端生成文档索引；输入或配置变化时录制数据重新核对。

**真栈冒烟与 LLM 评分（§8.3）。** 真栈按明确格式/服务/模型组合单独报告，未配置报告未执行、不以 skip 算通过；LLM 评分留作后续报告能力、不作首期硬门禁——与您的意见一致。
